What this is

Sneakernet is a tool for people who need to communicate safely when they cannot trust the network — or when there is no network at all. Messages are encrypted end-to-end before they leave your device. Nobody operating this relay can read them. There is no sender field, no addressing header, and no metadata linking any block to any identity. Blocks look like random bytes to everyone except the intended recipient.

Everything stored and exchanged is a fixed 4096-byte block of opaque data. Blocks spread through the network by epidemic routing: each node shares blocks with peers, who share with theirs. This node is one relay in that network — it stores incoming blocks and syncs them with other sneakernet nodes. When your device connects, it fetches blocks and tries to decrypt them. Only the ones addressed to your key will open.

There are three ways blocks move: relay nodes like this one (internet-accessible, community-operated), LAN sync (nodes on the same local network find each other automatically), and physical sync — blocks exported to a USB drive and handed to someone, who plugs it in and absorbs the data. There is no central point to shut down, no account to deactivate.

Using the browser client

The browser client at /app lets you send and receive messages from any device without installing anything. All cryptography runs in your browser — this server never sees your keys or your plaintext.

The browser client has real limitations. For anything time-sensitive or high-stakes, a native node or phone app is much safer.
  • Received messages are not saved. Decrypted incoming messages live in memory and vanish when you close or reload the tab. Sent messages are saved in browser storage and survive reloads. Re-scanning recovers received blocks still held by the relay.
  • Keys are this browser only. Identities live in IndexedDB for this browser on this device. A different browser, an incognito window, or clearing browser storage means starting over.
  • Keys are encrypted at rest. Private keys are sealed in IndexedDB with a vault password you set on first use. They only live in memory while you are unlocked — closing the tab or clicking Lock clears them.

Running your own node

Anyone can run a relay and contribute storage and bandwidth to the network. The more people running nodes, the longer messages survive and the harder the network is to disrupt. Running a node is an act of mutual support — you are helping everyone who uses this network maintain their ability to communicate.

Source code and setup instructions: github.com/brendanbenshoof/sneakernet. See RUNNING.md in the repo for relay configuration, storage limits, and peering options.
